1. Introduction & How This System Fits Together

The OMSI Countdown Tools are a family of pages that all share one Firebase Realtime Database project. Understanding how they relate to each other will save you a lot of confusion later on:

  • omsi_tools_extra.html — the admin tool covered by most of this guide. This is where timetables, stops, vehicles, curtailments and settings are all managed. It requires login.
  • omsi_live_tracker.html — the public live tracker. No login required. Shows live/upcoming departures for a chosen route, vehicle allocation working, and history lookup.
  • omsi_arrivals.html — the countdown/arrivals board. Designed to be left running on a screen at a bus stop or in a waiting area, showing the next few departures for one specific stop.
  • rsg_viewer.html — a companion tool focused entirely on the Route Schedule Generator's running number calculator (vehicle duty/crosslink planning). Reads and writes the same /rsgConfigs data as the RSG section of Tools Extra.
Key concept: nothing you do in the RSG section of Tools Extra is visible to passengers until you either click Add Preview to Live Schedule or apply a Scheduled Task. Saved/draft configurations only affect the admin tools until they are pushed live.

2. Admin Login & Initial Setup

Access to all management tools requires authentication.

  1. Navigate to your omsi_tools_extra.html page.
  2. You will be presented with the Admin Login form.
  3. Enter your registered Email and Password.
  4. Click the Login button.
  5. Upon success, the main menu bar will appear, granting you access to all tool sections your role permits (see the next section).
An Auto-Logout Timer can be configured in App Settings, which will sign you out automatically after a period of inactivity — useful on shared/public computers.

3. Understanding User Roles & Permissions

Every account has exactly one role, assigned in User Management. Your role determines which menu sections you can see and what you're allowed to write to the live database. Roles are enforced by the Firebase security rules, not just hidden in the interface — so even if a button were visible, the underlying save would be rejected for a role that isn't permitted to write to that data.

RoleTypical Access
AdminFull access to every tool, including User Management, App Settings and fare charts. The only role that can create/edit other users or change roles.
ModeratorCan manage schedules, stops, vehicles, curtailments, colours and route operator changes. Cannot manage users or certain sensitive settings.
ControllerFocused on day-to-day service intervention (curtailments, live trip adjustments) rather than long-term schedule editing.
Standard UserMinimal/read-oriented access, useful for staff who just need visibility without editing rights.
If a menu button appears to do nothing, or a save fails with a permissions-style error, the most likely cause is that your role doesn't have write access to that particular data path. Ask an Admin to check your role in User Management.

4. Master Stop Viewer

Navigation: Top Menu Bar → Bus Stops

This is the central hub for viewing and managing all bus stop definitions in the system. It is the single source of truth for stop information — every schedule entry references a stop from this list by its Stop ID.

Example: Master Stop List Entry

Francis Street (L) Towards: Althorpe, Ashby or Skippingdale Stop ID: BP1114 Status: Open
4 9 10 11 12 22 31 35 37 ...and 8 more.
Edit Name / Direction
Delete Stop Definition
Close Stop

Key Functions:

  • Add New Stop Definition: Create a new master stop record that can then be used in the Route Schedule Generator.
  • Filter List: Use the search box to filter the list by name, ID, direction, status, or a route number serving the stop.
  • Edit Name / Direction: Lets you change the stop's name and "towards" text. This change will propagate to all schedules using this stop.
  • Delete Stop Definition: Permanently removes the stop and all its entries from all schedules.
  • Close/Reopen Stop: Toggles the operational status of the stop, which affects the live arrivals board (a closed stop shows a "Bus stop closed" message instead of departures).
Renaming a stop here is much safer than trying to fix the name inside individual RSG configurations one at a time — the rename propagates everywhere automatically.

5. Route Schedule Generator (RSG)

Navigation: Top Menu Bar → Route Schedule Generator

This is the core tool for creating and managing timetables. A "configuration" (or config) represents one route + destination + operating profile + stopping pattern + first-departure times combination. Most routes will have several configs (e.g. one per direction, per day-type).

Saved Configurations

  • Schedule Selected...
  • Route: 4
  • 4 to Lakeside - MF, Sa Rename ✕

5.1 Building a Configuration

Enter the route name, tick which Operating Profile code(s) it runs on (e.g. MF, Sa, Su — see School Holiday Periods & Operating Profiles List for what these codes mean), the destination display name, the stop sequence, and the first departure time(s)/headway. Once the required fields are complete you can generate a preview.

5.2 Key Actions

  • Generate Preview: After defining all parameters, see the generated schedule (every individual trip/stop-time this configuration produces) before committing anything.
  • Add Preview to Live Schedule: Adds the previewed entries straight to the main live schedule immediately, prompting you to OVERWRITE (replace this route+profile+destination entirely) or ADD (append alongside anything already there). Use this for immediate changes.
  • Save This Configuration: Saves the setup to /rsgConfigs for later editing/reuse. This does not touch the live schedule by itself.
  • Schedule This for Later...: Sends the configuration to the Scheduled Tasks module with a future go-live time, instead of applying immediately. This is the recommended route for planned service changes (e.g. "from next Monday").

5.3 RSG Drafts

Drafts are staging copies of a configuration, kept completely separate from the live /rsgConfigs list until you're ready. A draft has no effect whatsoever on the live schedule, the arrivals board, or the main Saved Configurations list while it remains a draft — it's a safe place to prepare and review changes.

  • Copy Selected to Draft...: Takes one or more ticked saved configurations and creates draft copies of them.
  • Each draft card shows who created it, and its route/destination/profile, plus two actions: Activate Now (promotes the draft into a real live config, ready to be scheduled/applied) and Delete Draft (discards it without going live).
  • Drafts can also be opened in the RSG Viewer's running number calculator for full editing, including running numbers and crosslinks, exactly like a live config.
Use Drafts when you want to prepare next month's timetable changes over several sessions without any risk of accidentally affecting today's live service.

6. School Holiday Periods & Operating Profiles List

Navigation: Top Menu Bar → School Holiday Periods & Operating Profiles List

This section manages two lists that control which trips run on which calendar days:

  • Operating Profile codes — the master list of valid codes (e.g. Mo, Tu, We, Th, Fr, Sa, Su, MF, MFSch, MFNSD, bank holiday names, etc.) that can be ticked when building an RSG configuration. Add a new code here before it can be used elsewhere.
  • School Holiday Date Ranges — start/end dates with a description (e.g. "Summer Holidays 2026"). The system automatically treats any date inside one of these ranges as a school holiday, which changes which profile applies (school-day-only trips, marked Sch, are suppressed; non-school-day trips, marked NSD, run instead).
Keep the school holiday list at least a year ahead where possible — both the Arrivals board and the Live Tracker calculate "is today a school holiday?" using exactly this list, so an out-of-date list will show the wrong service pattern automatically at the start of a new term.

7. Day Profile Override

Navigation: Top Menu Bar → Day Profile Override

Sometimes a single calendar date needs to run a different pattern than the normal day-of-week/school/bank-holiday logic would produce — for example a special event, an emergency reduced service, or a one-off diversion day. This tool lets you force specific Operating Profile code(s) to apply, for specific routes, on one chosen date, without touching the underlying RSG configurations at all.

  1. Pick the Date to override.
  2. Tick which Operating Profile code(s) should apply on that date.
  3. Select which route(s) the override applies to (or leave unrestricted to apply to all routes).
  4. Click Apply Profile(s) to Selected Routes.

Active and upcoming overrides for the next 12 months are listed below the form, each with a Clear Override option to remove it early.

A Day Profile Override changes what the public pages compute for that date — it takes effect immediately (or from the moment the date arrives) with no further action needed, unlike RSG changes which require a preview/apply step.

8. View Departures

Navigation: Top Menu Bar → View Departures

See all scheduled departures from the live schedule for a chosen stop for today's operating profile — a quick way to sanity-check what you've just published without needing to open the public tracker separately.

Departures

  • 12 to Ashfield Campsite at 07:56 [P: MF]
  • 612 to Melior South School at 08:19 [P: MFSch]

9. Key Departures

Navigation: Top Menu Bar → Key Departures

A live monitoring dashboard showing the first and last departures of the day for every service, side by side. It refreshes automatically on a timer so it can be left open on a second monitor for quick operational awareness (e.g. spotting a route with no early departure configured). A manual Refresh Now button is also available.

10. Events Calendar

Navigation: Top Menu Bar → Events Calendar

A calendar grid for the current month, highlighting days that have something notable configured — a school holiday, a bank holiday, a Day Profile Override, or a scheduled task/deletion due that day. Use the Previous/Next buttons to move between months, and click a day for details. This gives a quick "what's different about this date?" overview without checking five separate tools.

11. Scheduled Tasks & Deployments

Navigation: Top Menu Bar → Scheduled Tasks

This module manages timetable updates that have been queued from the RSG section (via Schedule This for Later...) for a future go-live time, rather than applied immediately.

Batch Go-Live: 17/06/2026, 04:30:00 (pending)

Contains 2 update(s). Applying replaces entire Route 12.

Apply This Batch Now
  • Apply All for Selected Go-Live Time: Select a go-live time from the radio buttons to apply all tasks scheduled for that time in one go.
  • Apply This Batch Now: Appears for each batch of updates. Clicking it applies all changes in that batch, overwriting the entire schedule for the affected route(s)/profile(s)/destination(s) — any old entries for that combination are cleared first so nothing is left behind.
  • Cancel: Individual tasks can be cancelled and removed from the queue before their go-live time arrives.
Tasks are never applied automatically — an admin always has to click Apply This Batch Now (or the "Apply All" option) once the go-live time has passed. A banner appears automatically once a batch becomes due, as a reminder.

12. Schedule Route Deletion

Navigation: Top Menu Bar → Schedule Route Deletion

The deletion counterpart to Scheduled Tasks — lets you queue up the complete withdrawal of a route for a future date/time (for example, a route being discontinued at the end of a contract). Select the route, choose the go-live date/time, and click Schedule Deletion. The route continues running normally right up until that moment, at which point the deletion executes automatically the next time an admin applies due tasks.

13. Global Route Deletion

Navigation: Top Menu Bar → Global Route Deletion

Destructive, immediate, and has no undo. This removes all schedule entries, curtailment points and related configuration for the selected route(s) straight away. Only use this for a route you are certain should be removed right now — for anything planned ahead of time, use Schedule Route Deletion instead.

Select the route(s) to remove from the tile picker and click Delete Selected Route(s) Globally.

14. Route Profile Deletion

Navigation: Top Menu Bar → Route Profile Deletion

A more surgical alternative to Global Route Deletion — removes schedule data for one specific route + destination + operating profile combination, while leaving the rest of the route untouched. Useful when, say, a school-day-only journey needs withdrawing but the rest of the route's service should continue exactly as before.

  1. Select the route and destination (from dropdowns, or type to search).
  2. Tick which profile(s) for that destination should be deleted.
  3. Click Delete Selected Profile(s).

15. Enhanced Destination Update

Navigation: Top Menu Bar → Enhanced Destination Update

A bulk find-and-replace for destination display names across the whole system in one operation — the live schedule, every matching saved RSG configuration, and any curtailment points that reference the old name are all updated together.

  1. Optionally restrict the update to specific route(s), or leave blank to search every route.
  2. Select the exact old destination name from the list of existing destinations (don't type it freehand — it must match exactly).
  3. Enter the new destination name.
  4. Click Execute Full System Update.
This is the right tool for a destination re-wording (e.g. tidying up "Ashby Sainsburys" to "Ashby, Sainsbury's") that would otherwise require editing dozens of individual RSG configurations by hand.

16. Operational Points

Navigation: Top Menu Bar → Operational Points

Define official points where a service can be curtailed (short-turned). These points become available for selection in the other intervention tools below — you cannot curtail a trip to an arbitrary stop; it must first be registered here as an approved curtailment point for that route/destination.

Currently Defined Curtailment Points

  • Last Stop: Frodringham Community Centre (LE39) Displays As: "East Common Lane, Warwick Road" Return From: Frodringham Community Centre (LE38)
    Edit Delete
  • Select a route and destination, then pick the stop that becomes the temporary last stop.
  • Specify the stop the return journey resumes from (often the equivalent stop on the opposite side of the road).
  • Optionally give it a custom "displays as" name (e.g. a shortened blind/destination text).
  • A Copy From... button lets you duplicate an existing route's points onto another route that shares the same corridor, saving re-entering them from scratch.

17. Live Trip Intervention & Mass Route Curtailment

Navigation: Top Menu Bar → Live Trip Intervention

This section has two related but distinct capabilities:

17.1 Curtailing a Single Trip

  1. Select the route and destination, then click Fetch Trips to load today's scheduled trips.
  2. Pick the individual trip that needs adjusting and curtail it at one of the pre-approved Operational Points.

This only affects that one specific journey — every other trip on the route runs as scheduled.

17.2 Mass Route Curtailment (Universal)

A subsection of this same tool lets you curtail every trip on a chosen route + destination for a defined time window in one action — enter a start and end date/time and select the new temporary terminus, then activate. This is functionally identical to Service Leg Curtailment below (both write to the same mass-curtailment data); it's simply offered here too as a convenient second entry point while you're already looking at live trips for that route.

18. Service Leg Curtailment

Navigation: Top Menu Bar → Service Leg Curtailment

The dedicated, standalone tool for setting a temporary terminus for all trips on a specific route + direction for a defined period — the most common way to handle a planned road closure or diversion affecting a whole corridor.

  1. Select the route, the destination being curtailed, and any return-direction destination(s) that should be suppressed too.
  2. Choose the new temporary terminus from the pre-approved Operational Points list.
  3. Enter the start and end date/time for the curtailment.
  4. Click Activate Service Curtailment.

Active & Upcoming Service Curtailments

Active and upcoming curtailments are listed with a Lift Now option to end one early, e.g. if roadworks finish sooner than planned.

19. Global Route Colours

Navigation: Top Menu Bar → Global Route Colours

Sets the display colour for a route's tile (as seen throughout the Live Tracker and Arrivals board) globally, wherever that route appears. Select a route, choose a colour using the picker or one of the preset buttons (Day Bus, Night Bus, School Bus, Rail Replacement), then click Save Global Colour. A Remove Colours For Withdrawn Routes button helps tidy up entries for routes that no longer exist.

20. Stop-Specific Route Colours

Navigation: Top Menu Bar → Stop-Specific Colours

Occasionally a route should show a different colour only when displayed at one particular stop (for example, distinguishing two services that share a number at an interchange). Select the stop, then the route(s) at that stop to recolour, pick a colour, and click Save Colour for Selected Route(s) at this Stop. A stop-specific colour always takes priority over the global colour at that one stop only.

21. Vehicle Allocations

Navigation: Top Menu Bar → Vehicle Allocations

Controls which fleet vehicles the Live Tracker randomly assigns to a route's running numbers when no real sighting data is available yet. The workflow is route-centric: pick a route first, then populate its vehicle pools.

  • Common Vehicles & Rare Vehicles: paste fleet number/registration pairs, one per line, tab-separated — this pastes directly from an Excel column pair.
  • Rare Chance (%): a slider setting the probability that a rare vehicle (rather than a common one) is picked for a given working.
  • Sub Vehicle: assign a specific cover/substitute vehicle to one running number, overriding the random pool just for that duty.
  • Click Save Vehicles & Rare Chance For This Route to store the allocation. The Currently Configured Routes list below shows every route with an allocation, each with a delete option.

22. Route Operator Changes (ROC)

Navigation: Top Menu Bar → Route Operator Changes

Tracks which operator (e.g. First, Stagecoach, Arriva, Kelly Group) runs a route from a given date onward — used to label the route correctly on the public Live Tracker's page heading ("{Operator} - Route X") once an operator handover takes place.

  1. Select the route(s) affected from the tile picker.
  2. Choose the Effective Date the new operator takes over.
  3. Type the New Operator name.
  4. Click Add Change for Selected Routes.

The Active Operator Changes list below shows every change ever recorded, grouped by date, each showing the previous operator so you can confirm the handover is correct, with a delete option per entry.

A change takes effect from the moment its date arrives — there's no separate "apply" step. It's driven purely by comparing today's date to the effective date you entered, so an entry dated for a future date will simply do nothing until that day arrives.

23. App Settings

Navigation: Top Menu Bar → App Settings

  • Auto-Logout Timer: minutes of inactivity before you're automatically signed out of Tools Extra (enter 0 to disable).
  • Build Mobile Arrivals Index: a one-click button that pre-processes the full schedule into a per-stop index, dramatically speeding up the Arrivals board on mobile devices/low-powered screens. Run this after making large schedule changes if the mobile arrivals board seems to be using stale data.
  • Sync RSG Stop Names: a one-time repair utility that refreshes the cached stop name/"Towards" text stored inside every saved RSG configuration, to match the current Master Stop Viewer list. Useful after a bulk stop-renaming exercise that pre-dates automatic syncing.

24. User Management

Navigation: Top Menu Bar → User Management

Admin only. Create, edit and manage every account with access to Tools Extra.

  • Add a new user by entering their email, a password (optional when just editing an existing account), and selecting their role.
  • Clicking an existing user in the Existing Users list switches the form into edit mode for that account.
  • A user's status can be set to suspended (with an optional lift date) or archived, without deleting their account outright.

25. Live Tracker (omsi_live_tracker.html)

The public-facing tracker. No login is required to use it. Visitors can:

  • Search for a route number to see its currently live/upcoming departures, split by direction, with a vehicle fleet number, registration and running number shown for each service where known.
  • See the page heading automatically show the correct current operator for that route (see Route Operator Changes).
  • Search for a specific fleet number/registration across all routes, and "watch" a bus to keep track of it.
  • View a "Rare Workings" page listing all currently active rare-vehicle workings across the whole network.
The tracker caches each route's schedule locally in the browser (shown as "Lazy Load (Cached)" in the refresh indicator) so repeat visits to the same route are instant; it still listens live for updates in the background and refreshes automatically when new data arrives.

26. Countdown / Arrivals Board (omsi_arrivals.html)

Designed to be left running full-screen on a display at a bus stop, waiting room or similar. Shows a clock, the selected stop's name/direction, the route tiles serving that stop, and a rolling countdown of the next few departures — refreshing automatically every few seconds.

  • Click the stop name/header to open the stop-picker and choose a different stop.
  • The last-selected stop is remembered in the browser, so the display resumes on the same stop after a page reload or device restart.
  • An administrator can push a scrolling custom status message to this board from App Settings (e.g. for a service disruption announcement), which appears as an extra scrolling row.
  • On mobile/low-powered devices the board relies on the pre-built per-stop index (see Build Mobile Arrivals Index in App Settings) rather than downloading the entire live schedule, for performance reasons.

27. RSG Viewer & Running Number Calculator

A companion admin tool focused entirely on vehicle duty planning — working out which physical vehicle/running number covers which trip throughout the day, including where routes "crosslink" (the same vehicle continuing onto a different route number after its last trip).

  • Select a saved configuration (or a Draft — see RSG Drafts) to open the "Number suggestions" panel, which builds a chronological duty chain across both directions and suggests running numbers automatically.
  • Crosslinks let a running number carry over from one route/config to another for vehicles that work multiple routes in a single shift.
  • A PDF export groups every duty by route for printing/distribution to drivers.

28. How the Data Fits Together (Firebase Overview)

You do not need to understand this to use the tools day-to-day, but it can help make sense of some behaviour (especially around why a change appears in one place and not another):

Firebase PathWhat it holds
/liveSchedule/schedulesByRouteThe authoritative live timetable actually shown to passengers, organised by route → operating profile → destination → list of stop-time entries.
/rsgConfigs / /rsgConfigDraftsThe saved "recipes" used to generate the live schedule (Route Schedule Generator). Editing these has no effect on passengers until applied/scheduled.
/scheduledRouteUpdates / /scheduledRouteDeletionsQueued future changes awaiting an admin to apply them once due.
/vehicleAllocations / /vehicleFleetWhich vehicles can appear on which routes, and the master fleet list.
/liveServiceInterventions/massCurtailmentsActive/upcoming curtailments affecting a whole service leg (from both Service Leg Curtailment and Mass Route Curtailment).
/operationalOverridesDay Profile Overrides for specific calendar dates.
/routeOperatorChangesByDateDated operator handovers used by Route Operator Changes.
/settingsApp-wide configuration: custom route colours, stop-specific colours, school holiday ranges, the operating profile code list, and the arrivals board's custom status message.
/usersAdmin account records and roles.
Every top-level path has its own read/write security rule. Public pages (Live Tracker, Arrivals) can only read paths explicitly marked with public read access — if a brand-new feature's data doesn't appear on a public page, this is the first thing to check (see Troubleshooting below).

29. Troubleshooting & Common Issues

29.1 "I made a change but the public page still shows the old data"

  • Check whether the change was actually applied live, or is still sitting as a saved config/draft/scheduled task awaiting go-live.
  • Hard-refresh the public page (the browser may be showing a cached copy of the page itself, separate from the live data it displays).
  • If it's a brand-new type of data (not schedule entries), it's possible the Firebase security rules haven't been updated yet to allow public read access to that path — this looks identical to "not updating" from a user's point of view but is actually a permissions issue. Ask whoever manages the Firebase project to check the Realtime Database rules for that path.

29.2 "The tracker shows both old and new running numbers/vehicles for the same route"

This happens if a schedule update changed a destination or operating-profile's exact wording (spacing, punctuation, capitalisation) at the same time as other details like vehicles/running numbers — the old and new data can briefly end up stored under two slightly different internal keys. Re-applying the update (re-running the Scheduled Task, or re-saving the route from RSG) will clear out any stale leftovers, since the current save process always clears a route's existing data before writing the fresh version.

29.3 "A large route/schedule save fails with a size or payload error"

Very large routes (many thousand entries) are saved in smaller pieces automatically to stay within Firebase's limits — if you see an error mentioning payload size, try the save again; if it persists, it usually means the underlying automated re-indexing process needs attention rather than the schedule data itself.

29.4 "A Day Profile Override or Route Operator Change effective 'today' isn't showing yet"

These features compare the effective date you entered against today's date. If you're checking right around midnight, allow a few minutes for the date to roll over consistently across all pages before assuming it's broken.

29.5 "My browser is showing a storage/quota warning"

Tools Extra keeps a small amount of state (like which menu section you last had open) in the browser's local storage. If your browser's storage is full, this is harmless and self-corrects — the tool will simply not remember your last-open section between visits until space frees up.
